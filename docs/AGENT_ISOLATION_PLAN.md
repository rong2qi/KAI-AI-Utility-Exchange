# Exchange Agent 隔离渐进计划

日期：2026-10-09。依据用户要求，按“从尚无 Agent 工具隔离到具备可验证隔离，再逐步减少可利用风险”理解；不承诺提示词注入风险归零。当前已授权制定计划，事务存储实现继续按既有队列推进。此计划不自行开启 Agent 工具、生产部署或新增付费调用。

参考：[Anthropic 官方沙箱说明](https://www.anthropic.com/engineering/claude-code-sandboxing)。其核心是同时限制文件和网络，并将长期凭据放在隔离执行环境之外。借鉴安全目标；是否采用其开源 runtime，须先固定版本并审查许可、维护、依赖及宿主环境，不等于已选型或安装。

| 阶段 | 用户体验目标 | 实现范围 | 可证伪验收 |
|---|---|---|---|
| 0：资产与信任边界 | 输入恶意文本不会触发购买、扩权或泄露密钥 | 将 prompt、供应商输出、外部文档标为不可信数据；明确账户、账本、密钥、控制面保护对象 | prompt 不能选择管理动作；正文和回执隔离；列明现有代码与待接入差距 |
| 1：显式业务命令 | 前端或模型建议都必须经过统一授权 | 在现有 Runtime seam 引入类型化 command；保留兼容入口；工具执行前按账户、资源、用途逐次授权 | 直接请求后台、伪造能力字段、模型输出伪造命令均不能绕过鉴权 |
| 2：隔离执行进程 | Agent 仅能处理本任务文件；异常可停止 | 独立低权限工作进程和临时工作目录；只读输入、受限输出；时间/内存/进程/磁盘限制；不挂载宿主 Docker socket、SSH 目录或服务密钥 | 越目录、符号链接、子进程逃逸、资源耗尽、取消后残留任务负向验证 |
| 3：文件与网络联合隔离 | 任务可访问必要服务，越界访问被阻断 | 根据 Linux/macOS 目标选择 OS 隔离 adapter；默认无任意外联，只经独立出口代理；域名/IP/端口及重定向逐次检查；拦截内网/元数据目标与 DNS 变更绕过 | 直连、重定向、DNS rebinding、替代协议、子进程联网、读取后外传均实际测试；单有文件或网络一项不记为通过 |
| 4：凭据代理与结果通道 | 用户无需把供应商密钥交给 Agent | 凭据仅由可信 broker 按最小 scope 注入实际请求；隔离环境仅拿短期任务能力；日志白名单；结果内容不执行 | 环境变量/文件/错误/日志/模型输出取密钥失败；跨账户、过期能力、管理操作被拒绝 |
| 5：隔离 staging 与晋级 | 可验收、可撤销、可回滚 | 在本项目独立环境组合；红队输入、故障恢复、审计和回滚；通过后才启用对应工具能力 | 固定源码和隔离配置、直接运行证据、资源清理、回滚结果；未知能力保留待验证状态 |

前台隐藏按钮不是安全边界；后端授权是业务边界，OS 文件/网络/进程限制是执行边界。二者不能互相替代。模型输出只能提出候选工具调用，不能成为授权来源。

本计划与存储路线衔接：先完成权益账本的持久化和恢复，使 Agent 取消、超时、崩溃时不会自动退款或重复调用。后续 Agent 工作进程不得直接访问数据库文件，只通过已授权的后台接口。数据库 adapter、Provider adapter 和隔离 adapter 分开替换。各阶段需保留实施前后证据；只有用户确认才标记 ACCEPTED。
