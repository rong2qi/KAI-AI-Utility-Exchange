# 跨小时只恢复结算

2026-10-12，承接用户批准的下一切片。目标：过期后恢复已受理且已保存成功结果的账务，不再提交推理；未知结果进入待确认分流，不凭客户端声明扣量、退款或重发。此切片不使用 MixRoute 的 USD 55 或 Dahono 额度。

接口：`POST /v1/settlements/recover`，Bearer KAI Key，JSON 仅含 `idempotency_key`。调用方不能提交账户、供应商、输入、结果、用量、时间或强制成功字段。不存在的操作返回 404，不新建认领。

恢复服务独立注入时钟、Key 验证器、恢复存储与回执 Writer，不依赖 Provider adapter。恢复存储在原端口之上提供账户内只读查找；不要求其他现有 adapter 实现同步快照。

授权：必须为原账户、原 Key、原 Grant，并有显式 `usage.recover` 能力；复用 Key/Grant 的 `receiptUntil` 作为已受理业务善后时限，检查 issuedAt、撤销及原资源范围。不能借另一份 Grant 扩权，计算能力和只读回执能力均不隐含恢复权限。恢复后的 Receipt 保留原请求身份和原受理时间。换 Key 后的恢复需独立授权方案，当前不隐式扩权。认证后、存储读取后、每次结算副作用前重新校验授权与时间。

结果：`settled` 返回已保存输出和回执；`pending_reconciliation` 返回有限的待确认原因，不返回 owner token、原始 Provider 输出或异常；`released` 表示原操作已释放，不再次启动。以上状态只描述旧操作，不授予新调用权。

九阶段数据来源沿用 SQLite 片：reserved/dispatching/uncertain 不自动接管或释放；provider_succeeded 起可继续；receipt_prepared 复用已固定候选；已完成状态读取原回执。计算与恢复共用一个结算函数，事务仍不跨 Provider I/O。并发恢复依赖预期状态、幂等写入与数据库事务，不新增自动重试。

验收：内存和真实 SQLite；跨窗恢复和数据库重开；旧操作不重扣；不存在的操作无认领；未知结果不变更；并发恢复/计算交错；越权、撤销、过期、错误 Grant、时钟跨越；HTTP 拒绝新增字段；真实 Provider 调用零。HTTP 响应超时不等于上游被终止，/goal 不是数据库认领或小时续期单位；每个新 Compute 都单独授权。

本切片的待确认流程是可查询、可分流的状态，不是已实现供应商自动对账：只有后续接入可信供应商记录/人工受保护裁决及审计后，才允许改变未知结果。任务级总预算、模型调用次数上限、硬执行截止、完整 Agent 调度与取消仍需另外实现，不能将响应超时当成这些能力已完成。
